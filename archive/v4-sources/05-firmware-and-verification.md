# 5. 펌웨어와 검증

## 세 빌드

| 빌드 | 내용 | Flash / SRAM |
|---|---|---|
| original | 보존 운영 원본2ms, MP3 API대역으로 시뮬레이션 | 4732 /364 bytes |
| candidate | D11/A3 기존 기능 제거,10ms×5 최소안 | 4700 /364 bytes |
| frontpanel | 최소안 +595 LED6 +A3 2초버튼, 비차단 대기 | 5292 /336 bytes |

숫자는 Arduino AVR Core1.8.8로 만든 **시뮬레이션용 빌드**입니다. 원본 소스/ZIP은 별도 보존했습니다. 실제 장치 업로드는 하지 않았습니다.

## 외부 표시·진행

SN74HC595N의 SER14=D11, SRCLK11=D13, RCLK12=D7. VCC16=5V, GND8=0V-L, /SRCLR10=5V, /OE13=0V-L. QA15/QB1/QC2/QD3/QE4/QF5에 각1.5kΩ과 LED를 연결합니다. 순서는 액자·조명·열쇠·RFID·책·완료이며, 통상 한 개가 켜집니다. 대기 중500ms 주기로 점멸하고 종료 후 완료LED가 켜집니다. QG/QH/직렬출력은 미접속입니다. 칩 근처100nF를 둡니다.

A3는 INPUT_PULLUP이며 외부4.7k 풀업·직렬1k·100nF를 추가한 NO 순간버튼입니다. 소프트웨어30ms 디바운스 후2초 유지하면 현재 센서 단계를1회 완료합니다. 계속 누르고 있어도 반복하지 않고 놓았다 다시 눌러야 합니다. 프로그램의20초·1초·10초 대기는 보존합니다. 대기 중 누름은 다음 단계로 예약하지 않습니다. 부팅 중 누름도 자동 진행으로 예약하지 않습니다.

원본의 blocking delay/종료 while은 비차단 phase로 바꿔 LED와 버튼 처리를 유지합니다. 부팅 모터 D4 LOW/D5 HIGH/ENA HIGH와 단계별 출력 순서는 보존했습니다. 화면은 pass 값으로 LED를 꾸미는 대신 실제 GPIO에서 전송·래치된595 비트를 표시합니다.

## 검증

AVR 시험 결과는 같은 펌웨어를 사용한 v5.3 보존본에서 확인할 수 있습니다.

- [기존4개 AVR 시험](../v5.3-preserved/tests/verification.json): 2ms/10ms 필터 차이, 최소안 기존 기능 제거, 전체 순서와 지연.
- [외부 조작부6개 AVR 시험](../v5.3-preserved/tests/frontpanel-verification.json): 595 래치, 짧은/바운스 입력 무시,2초1회, 유지 반복 방지, 기존 출력/대기, 대기 중 입력 소비, 정상 센서 순서.
- [v4 설계 검사 스크립트](tests__check-design.py): 공통 GND 연결, 전력 귀환 경로, 라벨 유일성, 문서 링크, 원본 보존, 계획 점유영역 경계/겹침.
- 브라우저에서 상/하 확대, 치수 부족 표시, GND/결선표, LED회로, 실제 수동 진행을 확인합니다. 과거 v2 브라우저 결과를 최신 결과로 표시하지 않습니다.

## 남아 있는 실물 코드 조건

동봉 레거시 소스의 `SpecifyMusicPlay(0,1)`는 동봉 헤더의1인자 선언과 맞지 않습니다. 시뮬레이션은 API대역으로 컴파일했으므로 MP3 통신·실음원 재생 성공을 증명하지 않습니다. 설치용 최종 펌웨어는 실제 KT403A 라이브러리/프레임에 맞춰 이 부분을 해결하고 실기 재빌드·재생 시험을 해야 합니다. 이 검토본을 바로 플래시 가능한 최종 설치본이라고 표시하지 않습니다.

AVR8js는 CPU·타이머·GPIO·ADC를 모델링하지만 SMPS 리플·서지·코일·접점·실제 센서 출력·모터 기구를 모델링하지 않습니다. 원본 enable HIGH와 리셋 접점 상태도 현장에서 확인합니다.

회로 근거: [TI SN74HC595 공식 자료](https://www.ti.com/lit/ds/symlink/sn74hc595.pdf).
